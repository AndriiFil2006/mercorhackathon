# Legal Expert Evaluation Backend

Stores fictional legal questions, AI answers, and structured human expert reviews. Exports reviewed records as JSONL for evaluation or training preparation. It does not train models or transmit records to Mercor. A correct expert verdict means expert approval, not universal legal correctness.

## Setup (Python 3.11+)

Run from the repository root in PowerShell:

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m alembic upgrade head
python -m app.seed
python -m uvicorn app.main:app --reload
```

On macOS/Linux, activate with `source .venv/bin/activate` and copy with `cp .env.example .env`. All subsequent commands run inside backend. SQLite paths and .env resolve relative to the working directory. No tables are created during app startup.

Swagger: http://localhost:8000/docs. OpenAPI: http://localhost:8000/openapi.json.

## Configuration

Defaults use deterministic simulated answers with no API cost. Set AI_PROVIDER=openai and OPENAI_API_KEY to use real generation; OPENAI_MODEL selects the model. Missing keys fall back to mock even when openai is selected. DATABASE_URL defaults to sqlite:///./legal_eval.db. CORS_ORIGINS is a comma-separated exact allowlist for localhost ports 3000 and 5173 by default. Keep keys in local .env, never version control.

## Workflow

These curl examples use POSIX shell quoting (use curl.exe or equivalent JSON files on Windows):

```sh
curl http://localhost:8000/health
curl -X POST http://localhost:8000/api/v1/questions -H 'Content-Type: application/json' -d '{
  "title":"Fictional contract dispute",
  "question_text":"Fictional Alder Studio receives desks late from fictional Birch Works. What facts affect remedies?",
  "domain":"Contract law",
  "jurisdiction":"New York, United States",
  "relevant_law_date":"2025-01-01",
  "difficulty":"medium"
}'
curl 'http://localhost:8000/api/v1/questions?domain=Contract%20law&difficulty=medium&offset=0&limit=50'
curl -X POST http://localhost:8000/api/v1/questions/QUESTION_UUID/generate
curl http://localhost:8000/api/v1/generations/GENERATION_UUID
curl -X POST http://localhost:8000/api/v1/evaluations -H 'Content-Type: application/json' -d '{
  "question_id":"QUESTION_UUID",
  "generation_id":"GENERATION_UUID",
  "reviewer_id":"demo-reviewer",
  "verdict":"partially_correct",
  "error_categories":["incomplete_answer"],
  "expert_explanation":"The answer omits analysis of the agreed remedy limitation.",
  "corrected_answer":"Review enforceability and scope of the remedy limitation before assessing available relief.",
  "confidence":3
}'
curl http://localhost:8000/api/v1/evaluations
curl -o evaluations.jsonl http://localhost:8000/api/v1/exports/evaluations
```

Replace UUID placeholders with response IDs. Citation objects support title (required), citation, url, and jurisdiction. References can be supplied on question creation for benchmark storage but never appear in public responses, generation prompts, or exports. There is deliberately no reference retrieval endpoint.

Lists return arrays with offset/limit pagination (default 50, maximum 200). Question lists also filter domain and difficulty. Creates return 201, missing records 404, invalid requests 422, and reviews of unfinished generations 409. Generation provider errors persist a failed record returned with 201 and a sanitized error_message; callers must inspect status.

Each export line contains schema_version, public question, immutable generation, and evaluation, including verification_status. Multiple reviews of one answer produce separate records; abstentions are included as expert_abstained. Unreviewed generations are excluded.

## Development and tests

```sh
python -m pytest -q
python -m alembic check
python -m alembic revision --autogenerate -m "describe schema change"
python -m alembic upgrade head
python -m app.seed
```

Review autogenerated migrations before applying them. Seed IDs are stable; reruns do not overwrite existing questions. Tests use migrated temporary SQLite files, dependency overrides, and only the mock provider. Completed and failed generations are immutable through ORM updates and SQLite update/delete triggers.

## MVP boundaries

No authentication: reviewer_id is a supplied label, not verified lawyer identity. Run locally or behind access controls; do not deploy publicly or store confidential client data. Human experts supply and assess authorities; citation URLs are stored, never fetched. Real OpenAI generation is configured but intentionally not exercised by unit tests. Calls run synchronously without a worker queue; a process crash during generation can leave a pending record. Reissue generation to create a new record. No automatic legal correctness scoring, fine-tuning, or Mercor integration is implemented.
